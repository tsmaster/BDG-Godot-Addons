- [ ] Re-check the leaked-resource warning at exit on newer Godot versions. It comes from `@export var children: Array[RetroMenuItem]` in `retro_menu_item.gd`: an exported typed array of the script's own class keeps the script alive at shutdown (an exit-time warning only, seen on 4.7.2 and 4.8-dev6). Untyped or `Array[Resource]` exports do not leak. If we publish the addon, consider `@export var children: Array[Resource]` (looser typing, needs casts) to avoid the warning.

- [ ] Consider a per-item `activated` signal (or an optional `Callable`) on `RetroMenuItem`, so simple menus can be wired without one big `item_activated` handler, for example `root.add_item("Attack", Action.ATTACK).activated.connect(attack)`. Deferred for now to avoid two ways of doing the same thing.
- [ ] Add checkbox and radio-button item types, for lightweight settings menus. Items are currently either actions (leaves) or submenus (parents). Open design questions:
  - Where the state lives. The likely answer is on the `RetroMenuItem` itself (for example `checked: bool`), since items are Resources and the game can read and set them. Another option is binding an item to a property on a game object.
  - How radio groups are defined: a group name on each item, or "all radio siblings under one parent form a group".
  - Signals: probably an `item_toggled(item)` signal, separate from `item_activated`, and toggling should keep the menu open instead of closing it.
  - Drawing (decided to try): draw them as text in the item's own font, `[ ]` and `[x]` for checkboxes and `( )` and `(x)` for radio buttons, placed before the item text. This suits the retro look and needs no textures or theme entries. Things to handle: cell width must include the indicator (measure the wider of the two states so the layout doesn't shift when toggled), text that starts after the indicator must line up across rows, and a proportional font may not align `[ ]` with `[x]`. Disabled items should use the disabled color for the indicator too.
  - Input (decided): `ui_accept` and click toggle the item without dismissing the menu, whatever the `close_on_activate` setting. Still to check: that this fits the `ui_left`/`ui_right` behavior.
